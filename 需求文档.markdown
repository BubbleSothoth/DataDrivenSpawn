# 数据驱动对象刷新系统设计文档

## 1. 项目目标

实现一个通用的数据驱动对象刷新系统。

系统应具有以下能力：

1. 根据刷新时间自动创建Prefab。
2. 根据JSON自动为对象添加Component。
3. 根据JSON自动初始化Component成员变量。
4. 不允许针对任何Component编写特殊代码。
5. 系统应完全依赖反射实现自动配置。

整个系统应具有高度可扩展性，以便后续支持Boss、子弹、UI、特效等所有对象。

# 3. SpawnController职责

SpawnController只负责：

- 读取Spawn文本
- 创建Prefab
- 调用ComponentInitializer初始化对象

不得负责：

- JSON解析
- Component添加
- 字段赋值
- 类型转换

SpawnController保持业务简单。

```
Dictionary<string, GameObject>

```

# 5. Spawn文本格式

每一行格式：

```
createTime\tcreateName\tposX\tposY\tposZ\tjson
```

示例：

```
1000    Enemy01    0    5    0    {...json...}
```

字段说明：

|字段|说明|
|----|----|
|createTime|刷新时间(ms)|
|createName|Prefab名称|
|posX|出生位置|
|posY|出生位置|
|posZ|出生位置|
|json|对象初始化数据|

json字段允许包含Tab。

因此建议：

读取前5列后，

剩余字符串全部作为JSON。

不要Split全部字符串。

# 6. JSON结构

采用如下结构：

```json
{
  "ComponentVar":[
    {
      "Component":"Enemy01Ctrl",
      "Variables":[
        {
          "Name":"targetPosition",
          "Data":{
            "x":0,
            "y":0,
            "z":0
          }
        },
        {
          "Name":"moveSpeed",
          "Data":5
        },
        {
          "Name":"bulletPrefab",
          "Data":"Bullet-001"
        }
      ]
    }
  ]
}
```

注意：

删除Type字段。

类型全部由反射自动推导。

# 25. 架构要求（必须遵守）

整个系统必须遵循 **开放-封闭原则（Open/Closed Principle，OCP）**：

> **对扩展开放，对修改关闭。**

具体要求如下：

## 25.1 核心业务模块保持稳定

以下模块属于系统核心模块：

- SpawnController
- ComponentInitializer
- ReflectionCache

在后续新增功能时，原则上不得修改上述模块的业务逻辑。

例如：

新增：

```
Vector4
AnimationCurve
Gradient
Sprite
Material
AudioClip
Texture
ScriptableObject
List<T>
Dictionary
```

等数据类型时，不允许修改：

```
SpawnController.cs
```

也不允许修改：

```
ComponentInitializer.cs
```

而应通过扩展类型转换器实现。

---

## 25.2 TypeConverter作为唯一扩展入口

所有数据类型转换逻辑必须集中在：

```
TypeConverter
```

例如：

```
Json

↓

TypeConverter

↓

object

↓

Field.SetValue()
```

ComponentInitializer不得出现：

```csharp
if(fieldType == typeof(Vector3))
```

或：

```csharp
switch(fieldType.Name)
```

所有类型判断必须由TypeConverter统一处理。

---

## 25.3 新增数据类型不得影响已有代码

例如：

当前支持：

```
float
Vector3
GameObject
```

后来增加：

```
Sprite
```

应仅需：

1. 新增Sprite转换器。
2. 在TypeConverter中注册。

不得修改：

```
SpawnController
```

不得修改：

```
ComponentInitializer
```

不得修改：

```
ReflectionCache
```

---

## 25.4 Component无需注册

新增脚本：

```
Boss01Ctrl
```

系统应自动支持。

不得：

```
switch(ComponentName)
```

不得：

```
if(Component=="Boss01Ctrl")
```

所有Component均通过反射自动发现。

---

## 25.5 TypeConverter推荐采用注册机制

建议采用注册式架构，而不是大量if/switch。

例如：

```
Dictionary<Type, ITypeConverter>
```

其中：

```
ITypeConverter
```

接口定义：

```csharp
public interface ITypeConverter
{
    bool CanConvert(Type type);

    object Convert(
        object jsonData,
        Type targetType,
        Dictionary<string, GameObject> prefabDictionary);
}
```

例如：

```
FloatConverter

Vector2Converter

Vector3Converter

ColorConverter

QuaternionConverter

GameObjectConverter

EnumConverter
```

启动时统一注册。

TypeConverter仅负责：

```
找到对应Converter

↓

执行Convert()
```

以后增加：

```
AnimationCurveConverter
```

只需新增一个Converter并注册即可。

---

## 25.6 ReflectionCache独立

Reflection缓存不得依赖任何业务逻辑。

缓存仅负责：

```
Type

↓

FieldInfo
```

任何Component均共享该缓存。

不得因为新增脚本而修改缓存实现。

# 26. 代码注释规范（必须遵守）

为了保证框架具有良好的可维护性，生成的所有代码必须包含完整、规范的中文注释。

## 26.1 注释语言

所有注释统一使用：

```
简体中文
```

不得使用：

- 英文注释；
- 拼音注释；
- 无意义注释。

---

## 26.2 XML文档注释

所有：

- public类
- public接口
- public方法
- public属性
- public字段（必要时）

均应添加XML文档注释。

例如：

```csharp
/// <summary>
/// 根据JSON初始化GameObject上的所有组件。
/// </summary>
/// <param name="obj">待初始化的对象。</param>
/// <param name="root">解析后的JSON数据。</param>
/// <param name="prefabDictionary">Prefab注册表。</param>
public static void Apply(
    GameObject obj,
    JsonRoot root,
    Dictionary<string, GameObject> prefabDictionary)
{
}
```

---

## 26.3 普通代码注释

对于：

- 复杂算法；
- 反射；
- 类型转换；
- 缓存；
- 性能优化；
- 容易误解的逻辑；

必须编写说明注释。

例如：

```csharp
// 首次访问某个Component时，缓存其FieldInfo。
// 后续所有对象直接使用缓存，避免重复反射造成性能损失。
```

而不是：

```csharp
// 获取Field
```

后者属于没有意义的注释。

---

## 26.4 注释内容要求

注释应说明：

- 为什么这样实现；
- 设计目的；
- 数据流向；
- 性能考虑；
- 特殊情况。

尽量避免只描述代码本身。

例如：

不推荐：

```csharp
// 给变量赋值
field.SetValue(...);
```

推荐：

```csharp
// 根据反射获取到的字段信息，将经过类型转换后的数据写入目标组件。
// 此处统一通过FieldInfo赋值，使系统无需针对任何Component编写特殊逻辑。
field.SetValue(...);
```

---

## 26.5 文件头注释

每个源码文件应包含文件说明。

例如：

```csharp
/******************************************************************************
 * 文件名称：ComponentInitializer.cs
 *
 * 功能描述：
 *     根据JSON配置自动为GameObject添加Component，
 *     并通过反射初始化所有公开字段。
 *
 * 设计原则：
 *     1. 不依赖具体Component类型；
 *     2. 所有初始化均通过反射完成；
 *     3. 类型转换统一交由TypeConverter处理；
 *     4. 遵循开放-封闭原则。
 ******************************************************************************/
```

---

## 26.6 方法内部注释

对于流程较长的方法，应按逻辑分段添加注释。

例如：

```csharp
// =========================
// 查找或添加Component
// =========================

// =========================
// 遍历变量列表
// =========================

// =========================
// 类型转换
// =========================

// =========================
// 字段赋值
// =========================
```

便于阅读和后续维护。

---

## 26.7 注释完整性要求

生成的代码应达到以下标准：

- 所有类均有说明；
- 所有公开接口均有XML注释；
- 所有复杂逻辑均有中文解释；
- 不出现"TODO"、"待实现"等占位内容；
- 不省略关键实现步骤；
- 保证代码可以直接用于生产开发，而非示例代码。

注释应与代码保持一致，不得出现过时、错误或与实现不符的描述。
